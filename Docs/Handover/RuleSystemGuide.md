# 规则系统指南

## 规则契约

校验问题由稳定的 `RuleId`、`CircuitValidationSeverity` 和分类/问题元数据标识。`CircuitValidationService` 聚合生产 Helper；报告代码消费真实问题，不能从中文正文推断 RuleId 或 Severity。

- **Error**：危险或无效接线，不能宣称结果正确。
- **Warning**：需要关注的教学、完整性或潜在安全问题，不一定是立即硬失败。
- **Info**：补充证据。

不要为了让报告“好看”而改 RuleId 或 Severity。现有基线和教学内容依赖这些契约。

## 新增规则步骤

1. 判断规则归属：电源电位、保护旁路、时间继电器旁路、电机/相序、元件不变量或控制结构。
2. 在对应生产 Helper 中实现，并由 `CircuitValidationService` 聚合。
3. 在生产问题构造处唯一确定 RuleId 与 Severity；快照写入器不得手写预期 Severity。
4. 使用活动工作区元件/导线与 Analyzer 证据，不能查找全场景对象。
5. 增加复用生产 Helper 的定点负向测试。
6. 确认所有正常真实模板不产生意外问题。
7. 仅在确认语义变更后更新规则基线。

## 避免误报

- 优先依据实际拓扑和端子语义，不要只依赖显示名称。
- 保留遍历预算与不支持拓扑处理；不能把超限静默当作通过。
- 标准模板是回归夹具；新规则命中它们时应先调查，不能自动生成新基线。
- Inspector 可以做已知检查面板误报的显示过滤，但这不能削弱生产校验。

## 必跑验证

规则修改后运行定点 Editor 测试、既有安全/负向测试、Inspector 模型测试和 `Tools/Tests/验证架构重构基线`。人工检查受影响家庭/工业模板及一个负向接线案例。不得用重新生成 expected 掩盖失败。
