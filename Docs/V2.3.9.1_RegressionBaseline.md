# V2.3.9.1 重构回归基线

## 目的

在抽离 `LocalInspectorPanel` 的报告数据与中文文案前，锁定当前稳定版本的真实模板加载、分析、校验与检查助手报告结构。基线工具位于 Editor 程序集，不会进入正式运行包，也不会修改模板 JSON、规则、场景、Prefab 或运行时业务逻辑。

## 入口

- `Tools/Tests/生成架构重构基线`：仅在 Play Mode 中由人工明确执行，使用真实模板目录和真实生成路径写入 expected 快照。
- `Tools/Tests/验证架构重构基线`：再次使用同一路径重新采集并与 expected 比较；不会覆盖 expected。
- `Tools/Diagnostics/采集 Demo 场景运行态对象计数`：按手动阶段写入 Demo 场景运行态证据，详见 [V2.3.9.1_DemoSceneRuntimeEvidence.md](V2.3.9.1_DemoSceneRuntimeEvidence.md)。

生成与验证均要求当前 Play Mode 已完成主界面、`WorkspaceController`、`SaveLoadService` 与 `LocalInspectorPanel` 初始化。工具缺少任一真实依赖会失败并记录异常，不会输出 PASS。

## 真实模板加载路径

每张模板依次经过以下生产路径，而非 `CircuitTestFactory`：

1. `CircuitTemplateCatalogLoader.TryLoad("Blueprints/Templates/template_catalog")`；
2. `CircuitTemplateLoader.TryLoad(item.resourcePath)`；
3. `CircuitTemplateSpawnService.Spawn(template, workspace, saveLoad.Catalog, ...)`；
4. `WorkspaceController.Components` 与 `WireManager.Wires`；
5. `CircuitStateAnalyzer.Analyze(...)`；
6. `CircuitValidationService.Validate(...)`；
7. 反射调用既有 `LocalInspectorPanel.CheckCurrentCircuit()` 与 `ExplainCurrentCircuit()`，只读取其 `reportContent` 结构。

模板加载会改变**当前 Play Mode**画布；工具完成后调用 `workspace.ClearDrawing(false)`。这不会保存场景或覆盖用户文件。执行前应在可丢弃的 Play Mode 会话中运行。

## 静态快照覆盖

基线生成时要求模板目录正好为 18 张：

- 家庭 8 张：单开单控、双控、空开控制、单相电能表、灯泡风扇并联、单开双灯、双开双灯、空开灯泡风扇并联。
- 工业 10 张：点动、连续运行、热继保护、正反转、点动加连续、双重联锁正反转、电气互锁正反转、自动往返、两电机时间继电器顺序启动、星三角降压启动。

每张模板记录：

- `TemplateId`、显示名、分类；
- 工作区元件数、导线数；
- 按 `DefinitionId` 排序的元件计数；
- 以 `DefinitionId + 稳定 ordinal` 表示的语义元件状态，不使用 Unity `InstanceID`；
- Analyzer 是否返回及电源、互锁、KT、限位、星三角、三相等结构化标志；
- Validation 的 `RuleId + Severity + Category`（排序后）；
- `COMPLEX_LOOP_OR_UNSUPPORTED_TOPOLOGY` 是否出现；
- Error/Warning 数量；
- 两个 Inspector 入口的结构快照。

文本在采集前会压缩空白和换行；浮点时间不以逐帧字符串比较。

## Analyzer 语义字段

利用现有 `CircuitStateResult` / `ComponentStateInfo` 的公开字段，当前覆盖：

- Breaker 输入/输出供电；
- KM 线圈与主触点 Analyzer 状态；
- KT 线圈、延时完成、15/18 与 15/16 触点状态、延时状态；
- SQ 触发状态；
- 三相电机、星三角电机、星/三角连接模式与供电接触器；
- 短路、电源冲突、互锁冲突、三相与不支持拓扑风险标志。

当前 Analyzer 没有统一公开的“自动往返位置/方向”或完整“电机正反转”结构化字段；这些必须通过后续动态阶段快照和关键文本验证补充，不在本轮改造 Analyzer。

## Inspector 报告策略

每个模板对以下两个真实入口分别保存：

- `CheckCurrentCircuit`；
- `ExplainCurrentCircuit`。

严格比较的结构字段：

- block 标题与顺序；
- block 类型；
- 推断 severity；
- 报告中出现的 RuleId；
- Error/Warning block 数；
- 是否含运行态段落；
- 是否含参数估算段落。

关键文本仅保存短语命中，不逐字符锁死长篇中文报告。当前短语集包括：`当前停止`、`当前正转运行`、`当前反转运行`、`KT 正在计时`、`星形启动阶段`、`三角运行阶段`、`热继主回路`、`电机绕过接触器`、`时间继电器控制旁路`。

## RuleId 合约基线

`ValidationRuleSnapshots.json` 固定记录以下 16 个 RuleId 的存在性与当前 Severity 合约：

`POWER_POTENTIAL_CONFLICT`、`LIVE_TO_PE_FAULT`、`NEUTRAL_PE_MISUSE`、`COIL_VOLTAGE_MISMATCH`、`BREAKER_OR_FUSE_BYPASSED`、`MOTOR_CONTACTOR_BYPASSED`、`REVERSING_INTERLOCK_MISSING`、`THERMAL_RELAY_CONTROL_BYPASSED`、`THERMAL_RELAY_MAIN_CIRCUIT_BYPASSED`、`TIMER_CONTROL_BYPASSED`、`STOP_BUTTON_BYPASSED`、`SELF_HOLDING_BRANCH_INCOMPLETE`、`REVERSING_CONTACTOR_CONFLICT`、`STAR_DELTA_PARTIAL_STARPOINT_SHORT`、`STAR_DELTA_INPUT_TERMINAL_SHORT`、`COMPLEX_LOOP_OR_UNSUPPORTED_TOPOLOGY`。

`COIL_VOLTAGE_MISMATCH` 记录为按失配方向决定的 `ErrorOrWarningByMismatchDirection`；其余规则记录当前固定 Severity。正常 18 张模板的实际报告也会一并入快照。负向规则仍由既有四个 Editor 菜单测试保护，不复制一套规则逻辑。

## 动态场景基线

动态行为必须在 Unity Play Mode 人工执行并按阶段记录，覆盖：

| 场景 | 阶段 |
|---|---|
| 点动控制 | 初始停止、按下启动运行、松开停止 |
| 连续运行 | 初始停止、启动保持、停止 |
| 热继保护 | 正常启动、FR 脱扣、电机停止、95/96 变化 |
| 正反转 | 正转、停止、反转、冲突保护 |
| 自动往返 | 启动、正向、右限位反向、左限位正向、停止保持 |
| 两电机顺序启动 | 停止、KM1/M1、KT Timing、到时 KM2/M2、停止复位 |
| 星三角 | 停止、星形、KT Timing、三角、停止复位、互锁确认 |

每个阶段应在 Inspector 中分别执行“检查当前电路”和“当前电路解释”，并通过取证窗口记录 Analyzer/Validation 计数与关键状态。时间只检查阶段与容差，不比较逐帧浮点字符串。

## 文件与人工更新约束

生成后的文件位于：

`Assets/EditorTests/Baselines/V2.3.9.1/`

- `TemplateStaticSnapshots.json`
- `InspectorReportSnapshots.json`
- `ValidationRuleSnapshots.json`
- `DemoSceneRuntimeEvidence.json`

这些 expected 只允许在人工确认当前版本稳定后由“生成架构重构基线”更新。验证失败不能自动覆盖基线。当前代码提交只提供工具与字段定义；首次真实 JSON 必须由 Unity Play Mode 采集后再单独审阅并提交。

## 当前未覆盖项

- 不自动点击业务按钮或推进 KT 计时；
- 不自动运行保存/导入用户图纸；
- 不使用反射读取 Button listener；
- 不以静态源码推断根层场景对象的运行态污染；
- 不替代现有通用电源安全、拓扑安全、保护旁路互锁、热继时间旁路 Editor 测试。
