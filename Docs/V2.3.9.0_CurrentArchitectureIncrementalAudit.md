## 当前问题分级

### P1：Demo.unity 存在大量活动的孤立电路对象，且与运行时工作区是双来源

- **证据**：`Demo.unity` 解析得到 2430 个 GameObject、678 个根对象、237 个 `CircuitComponent`、976 个 `TerminalView`、438 个 `WireView`；这些电路对象均位于根层级（典型名称 `Wire`、`km`、`m`、`power`、`dummy*`），且采样对象 `m_IsActive: 1`。
- **运行时链路**：`WorkspaceController.cs:122-179` 仅将 `SpawnComponent()` 创建的对象加入私有 `components`；`ClearDrawing:575-606` 只销毁该列表和 `WireManager.wires`；`CircuitComponent.cs:117-168` 只有 `Initialize(...)`，无从场景自动注册到 Workspace 的 Awake/Start 证据。
- **双来源**：`DemoRuntimeBootstrap.cs:13-69` 在 Start 且 `buildStarterCircuit: 1` 时先调用 `workspace.ClearDrawing()`，再 Spawn 6 个默认家庭元件和 9 条导线。场景残留对象不会进入该 private list，也不会被 ClearDrawing 清除。
- **影响**：当前静态证据表明残留对象通常不会进入 `workspace.Components` 或 `WireManager.Wires`，因而不直接污染 Analyzer/规则；但它们会扩大场景、造成编辑器层级噪声，并为未来任何 `FindObjectsOfType<CircuitComponent>` 或场景扫描引入双重来源风险。
- **修改风险**：中高，会影响 Demo 场景序列化和启动基线；不得在当前 UI 收口期直接删除。
- **推荐阶段**：架构稳定化后，先做“只读场景残留清单 + Play Mode 计数对照”，再决定迁移/清理；不要用脚本批量删除。

### P1：LocalInspectorPanel 仍承担检查编排、领域补丁和报告展示

- **证据**：见上表；尤其 `BuildIndustrialParameterEstimationSummary:1173-1692`、`TryFindProtectedThreePhaseMotor:1455-1593`、`BuildAutoReciprocatingMainRuntimeSummary:2162-2352` 仍留在 UI 类。
- **影响**：UI 调整继续向此类添加逻辑会放大回归范围；它已直接依赖 Workspace、Analyzer、Validation、工业规则和格式化器。
- **修改风险**：中；不能一次拆 UI、逻辑、文案。
- **推荐阶段**：下一个架构迭代先抽离报告组装，之后才评估流程编排服务。

### P2：主题入口已形成，但兼容入口和页面私有字体解析仍在

- **证据**：`MainUiTheme.cs:77-184` 统一缓存 `TitleFont`、`UiFont`、`UiFontBold`、`DenseUiFont`、`BodyFont`；`205-500` 统一 ApplyTextRole。残留直接入口见 `DemoUIController.cs:705`、`ElectricianCalculatorController.cs:709,715,774`、`EncyclopediaController.cs:934-967`。
- **影响**：小字号迁移后，后续刷新流程仍可能覆盖角色样式或走 Legacy fallback。
- **修改风险**：低，但涉及多页视觉回归。
- **推荐阶段**：冻结 UI 后按页面批次清理，不在架构第一刀中混入。

### P2：运行时页面创建策略并存，局部幂等但缺少统一约定

- `PageRouter.cs:42-140` 对 Gallery/Profile 是“查找或创建”；`TopNavigationController.cs:20-61` 对 PageRouter/CommonTools 是“查找或补挂”；`LocalInspectorPanel.Create:39-81` 是“查找、清空生成子节点、重建”；`TemplateLoadController.EnsureController:29-36` 是静态自动补挂。
- 这些路径各自有基本保护，当前未发现同类型 Controller 多挂载的源码证据；问题在于不同页面采用不同生命周期契约，未来更容易出现重复监听或场景壳与运行时壳竞争。

### 非问题/缺少证据

- `SimulationGalleryPageController.RefreshCards:296-304` 和 `ShowDetail:594-598` 会 Destroy 后重建卡片/详情，但每次先清理容器，且监听器随对象销毁，不是重复实例泄漏；这是当前数据量下可接受的 UI 重绘，属于后续性能评估而非 P0。
- `LocalInspectorPanel.Create:39-81` 会在已有面板时 ClearGeneratedChildren 并重建；在当前调用频率未知且按钮使用 `BindButton` 先 RemoveListener 后 AddListener 的条件下，没有足够证据升为 P1。需要 Play Mode 多次切换/重开计数验证。
- 常规 Awake/Start 内一次性 `FindObjectOfType`（如 `WorkspaceController.Awake:59-69`）不是高频问题。

## MainUiTheme 现状

`MainUiTheme` 已成为**主要**而非**唯一**的主题入口：

- 具备品牌、导航、工具栏、面板标题、元件卡片、日志、检查助手、内容页、详情页和系统信息等 40 个 `UiTextRole`。
- 具备 `TitleFont`（品牌）、`UiFont`（OPPO Sans Regular）、`UiFontBold`（实体 Bold）、`DenseUiFont`（系统中文高密度）和旧 `BodyFont` 兼容入口。
- `ApplyTextRole` 不强制覆盖调用方颜色，适合当前页面色彩语义。
- 尚未做到“所有字体/字号/颜色只在主题定义”：页面 Controller 仍有直接 font/fontSize/style 设置，且部分为合理的组件局部规格。

结论：**不要现在重写 MainUiTheme**；先记录残留并在未来逐页迁移。当前最重要的是防止新的页面再直接引入 LegacyRuntime。

## 推荐重构顺序

1. **第一刀：LocalInspectorPanel 的剩余报告数据/中文报告组装抽离。** 目标是把不修改 Unity UI 的 `BuildReportSummary`、`BuildCurrentCircuitExplanationReport`、验证摘要与估算文案逐步移至独立 formatter/composer；复用现有 `TeachingCheckReportFormatter`，不碰 Analyzer 图遍历。
2. **第二刀：检查流程编排抽离为服务。** 在第一刀输出稳定且有快照测试后，再把 `ExplainCurrentCircuit`、`CheckCurrentCircuit`、`AnalyzeCircuitState` 的调用次序移出 UI。
3. **后置：Demo.unity 残留电路对象治理。** 单独建立场景基线与回滚点，不能夹带在 UI/规则修改中。

## 当前绝对不要动

- `CircuitStateAnalyzer.Analyze/AnalyzePass`、图遍历和动态触点传播；当前缺少 Analyzer 快照/黑盒基线。
- `SimulationEngine`、`WorkspaceController` 的接线、撤销、保存加载和仿真生命周期。
- 规则 RuleId/Severity/模板 JSON。
- 已冻结的页面布局和字体资源；不要将主题整理与业务重构混在同一提交。

## 验证缺口

- 现有规则 Editor 测试覆盖通用电源、保护旁路、热继/计时器、拓扑安全，但不保护 LocalInspector 输出或 Analyzer 重构。
- 现有 `FinalUiAudit`、字体审计、Edit/Play 对照工具可发现字体、Rect、Shadow/Outline 和可见文本问题；不能证明重复 Controller、事件或页面实例在多次切换后不累积。
