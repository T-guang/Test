## 4. Demo.unity 电路对象审计

### 观察到的对象

场景根层级存在大量 Active 的电路相关对象，名称包括：

- `Wire`（大量）
- `km`、`km1`、`km2`、`km_forward`、`km_reverse`、`km_delta`
- `m`、`m1`、`m2`
- `power`、`power_1`、`power_2`
- `coil`、`fr`、`qf`、`fu`、`sb1`、`sb2`、`sq`、`sq1`
- `dummy0` 至 `dummy29`

它们不是 `SimulationPage/Workspace/ComponentLayer` 或 `WireLayer` 的正常子节点，而是根对象。场景中总计有 237 个 CircuitComponent、976 个 TerminalView、438 个 WireView。

### 与运行时工作区的关系

| 结论 | 代码证据 | 风险判断 |
|---|---|---|
| Workspace 只管理 Spawn 的元件 | `WorkspaceController.SpawnComponent:122-179` 才 `components.Add(component)` | 预置根对象没有自动进入 `workspace.Components` 的源码证据。 |
| ClearDrawing 只清理运行时列表 | `WorkspaceController.ClearDrawing:575-606` 遍历 private `components`，然后 `wireManager.Clear()` | 预置根对象不会被该流程删除。 |
| CircuitComponent 需显式 Initialize | `CircuitComponent.Initialize:117-168`；未发现自动向 Workspace 注册的 Awake/Start | 预置根对象很可能是历史/测试残留，而非当前可用工作区。 |
| 启动时另建默认家庭示例 | `DemoRuntimeBootstrap.Start:13-20` 和 `BuildHomeLightingCircuit:23-69`，场景 `buildStarterCircuit: 1` | 场景残留和运行时默认示例形成双来源。 |

**结论**：静态证据足以认定存在场景序列化残留和潜在双重生成风险；但没有 Play Mode `workspace.Components.Count`/`WireManager.Wires.Count` 采样，不能断言这些残留当前已经污染检查结果。该问题列为 **P1 场景卫生与未来维护风险**，不应在当前 UI 冻结期直接清理。

## 7. 结论

1. 场景 Controller 没有发现同类型重复挂载或 Missing Script。
2. UI 的运行时创建不是全部问题：弹窗、按需页面和动态列表有合理场景；真正的问题是缺少统一的“场景壳还是运行时壳”约定。
3. Demo.unity 的历史电路对象数量显著，且与运行时默认示例存在双来源，是本轮最明确的场景装配风险。
4. `MainUiTheme` 已成为主字体入口，但 `LegacyRuntime` 和私有 fallback 尚未完全退出。
5. 场景治理需要独立测试/回滚计划，不能与字体或 UI 小修混做。
