# V2.3.9.1 Demo 场景运行态取证

## 目的

`Demo.unity` 静态审计发现根层存在大量 `CircuitComponent`、`TerminalView` 与 `WireView`。当前源码证据显示 `WorkspaceController` 主要分析其私有 `components` 列表与 `WireManager.Wires`，但这不足以证明根层历史对象在 Play Mode 中一定不会污染 Analyzer 或 Validation。

本轮不删除、移动或保存任何场景对象。结论只能来自真实 Play Mode 计数。

## 取证入口

进入 Play Mode，等待默认示例加载后打开：

`Tools/Diagnostics/采集 Demo 场景运行态对象计数`

每完成一个阶段，在窗口填写阶段名并点击“采集当前阶段”；所有阶段完成后点击“导出取证 JSON”。工具仅读取当前场景，并将证据写入：

`Assets/EditorTests/Baselines/V2.3.9.1/DemoSceneRuntimeEvidence.json`

建议阶段名固定为：

1. `初始默认示例`；
2. `清空画布`；
3. `加载家庭模板`；
4. `加载工业模板`；
5. `保存并导入用户图纸`。

## 每阶段字段

- 全场景 `CircuitComponent`、`TerminalView`、`WireView` 数；
- 场景根对象数；
- 根层电路对象数；
- `workspace.Components.Count`；
- `workspace.WireManager.Wires.Count`；
- 私有 ComponentLayer / WireLayer 子对象数（只读反射）；
- 本次 Analyzer 与 Validation 实际传入的组件/导线数；
- Analyzer 是否返回；
- Validation issue 数。

Analyzer 与 Validation 的输入数来自同一次实际调用：

```csharp
analyzer.Analyze(workspace.Components, workspace.WireManager.Wires);
validation.Validate(workspace.Components, workspace.WireManager.Wires, state);
```

因此可直接回答根层残留是否进入当前工作区输入，而不是仅统计全场景对象总数。

## 页面生命周期轻量回归

依次切换六个顶部页面 20 轮：模拟电路、图纸集、仿真广场、元器件百科、常用工具、系统信息。完成后在同一窗口填写“切换六个页面 20 轮后”，点击“采集页面生命周期计数”，再导出。

记录：

- `LocalInspectorPanel`；
- `SimulationGalleryPageController`；
- `LocalProfilePageController`；
- `CommonToolsPageController`；
- `TemplateLoadController`；
- `EventSystem`；
- `Canvas`；
- 页面根对象数量。

本轮不通过反射读取或修改 Button listener，只用 Controller/Canvas/EventSystem 对象数发现重复创建风险。

## 判定规则

| 观察 | 结论 |
|---|---|
| 全场景对象很多，但 Workspace/Analyzer/Validation 输入仅随当前默认示例或模板变化 | 根层对象暂不构成已证实的运行态污染；单独立项处理场景源头，不要立即删除。 |
| 清空画布后 Workspace 与 Layer 都归零，而全场景根层对象仍存在 | 历史对象未由 `ClearDrawing` 管理，应继续检查其用途与启动成本。 |
| 模板加载后 Workspace 输入与全场景对象叠加增长，或 Validation 输入包含残留 | P0/P1 场景双重来源风险；停止重构，先定点处理场景装配。 |
| 20 轮页面切换后任一 Controller、Canvas 或 EventSystem 递增 | P1 重复创建风险；优先修复页面幂等性。 |
| 计数稳定、无 Console Error | 可以把“根层对象是否污染运行态”从假设降为已验证无污染，但仍保留场景清理候选项。 |

## 当前状态

本说明随工具代码提交。`DemoSceneRuntimeEvidence.json` 必须在真实 Unity Play Mode 阶段操作后生成；在未采集前，不得把静态计数当作运行态污染结论，也不得删除根层对象。
