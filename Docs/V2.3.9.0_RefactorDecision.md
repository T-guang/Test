# V2.3.9.0 重构决策与切口建议

## 决策前提

当前版本处于 UI 收口后、业务与规则冻结期。`CircuitStateAnalyzer`、`SimulationEngine`、`WorkspaceController`、模板和 RuleId 没有足够的快照/黑盒基线，不适合在本轮或下一小步中直接调整。Demo.unity 场景残留问题真实存在，但涉及序列化资产，不能在没有备份和运行时计数证据时清理。

## 推荐第一刀：B. LocalInspectorPanel 的报告数据/中文文案继续抽离

### 为什么是 B

1. `TeachingCheckReportFormatter` 已经存在，说明报告层已有可复用的目标边界；`LocalInspectorPanel` 仍保留大量与 UGUI 无关的字符串/估算/状态摘要方法。
2. 不需要改变 `CircuitStateAnalyzer.Analyze`、`CircuitValidationService.Validate`、Workspace 或任何 RuleId。
3. 可采用“输入结果对象 -> 输出段落列表/字符串”的纯 C# 形式，易做文本快照，回滚面小。
4. A（流程编排）在当前仍会跨工业/家庭、练习态、运行态覆盖、报告块显示；应等报告输出先固定再抽离。

### 第一刀范围

**纳入：**

- `LocalInspectorPanel.BuildReportSummary:536-607`
- `BuildCurrentCircuitExplanationReport:608-732`
- `BuildRuntimeDisplaySummary:993-1046`
- `BuildCircuitValidationSummary:1076-1139`
- 无 Unity 组件访问的格式化辅助方法，如 `FormatValidationIssue:1132-1139`、`ResolveRiskLevel:588-607`。
- 以现有 `TeachingCheckReportFormatter` 为基础扩展，或新增纯 C# `InspectorReportComposer`；不得同时存在两套同义的中文格式化规则。

**不纳入：**

- `AnalyzeCircuitState:749-753` 的调用位置。
- `ApplyRuntimeDisplayOverrides:755-992`。
- `TryFindProtectedThreePhaseMotor:1455-1593`、`BuildWireTerminalGraph:1482-1522` 等电气/拓扑判断。
- `AddReportBlocks/RebuildReportLayout/CreateReportBlock:2557-2879` 等 UGUI 呈现。

### 验收与回滚

1. 对家庭 8、工业 10 个模板生成“检查当前电路”和“当前电路解释”文本快照。
2. 对 V2.3.8.x 负向案例至少保存 Error/Warning RuleId 和报告标题顺序快照。
3. 新旧 formatter 并行一次，仅在开发环境比较差异；确认后移除旧调用。
4. 回滚只需将 `LocalInspectorPanel` 的 formatter 调用切回现有私有方法；不涉及 Scene/Prefab/模板数据。

## 推荐第二刀：A. 检查流程编排服务

在第一刀稳定、快照可用后，新增不依赖 UGUI 的 `InspectionWorkflowService`，由其接收 Workspace 的只读输入并返回报告模型。`LocalInspectorPanel` 只负责按钮、加载态和报告块显示。

建议先抽：

- `ExplainCurrentCircuit:381-404`
- `CheckCurrentCircuit:406-491`
- `AnalyzeCircuitState:749-753`
- `PrependCheckPanelRuntimeNotices:1048-1058`

仍不要抽/改：

- `CircuitStateAnalyzer.Analyze/AnalyzePass`
- `SimulationEngine` 的实时更新
- Validation Helper 拓扑安全预算
- 练习态提交/退出的业务状态写入

## 暂时不要动的区域

| 区域 | 原因 | 最低前置条件 |
|---|---|---|
| `CircuitStateAnalyzer` 图构建与迭代推导 | 4001 行核心逻辑，当前无完整黑盒/快照保护 | 18 模板 Analyzer 快照 + 关键连通性断言。 |

| MainUiTheme 全局整理 | UI 已冻结，且仍有页面私有兼容逻辑 | 每页字体截图和运行时字体审计。 |

## 架构重构前的最低测试基线

1. **真实模板快照**：加载家庭 8 + 工业 10，保存 Analyzer 状态摘要、Validation RuleId、Inspector 报告文本。
2. **Inspector 纯 formatter 测试**：相同 `CircuitStateResult/CircuitCheckResult` 输入得到相同报告块标题、顺序和等级。
3. **页面生命周期巡检**：连续切换六个页面 20 次，检查 `LocalInspectorPanel`、Gallery/Profile、TemplateLoadController 的实例数以及 Button listener 是否增长。
4. **Demo 场景对象对照**：Edit Mode 记录 237/976/438；Play Mode 分别记录根对象、`workspace.Components.Count`、`WireManager.Wires.Count`，确认残留是否参加运行态。
5. **现有规则测试继续全绿**：通用电源、拓扑安全、保护旁路、热继/计时器菜单测试，以及模板完整性检查。

## 是否建议现在进入重构

**建议进入“受限的第一刀 B”，不建议进入核心或场景重构。**

执行条件：

- 先补报告文本快照，不改变输出；
- 单独分支/单独提交；
- 不与 UI 字体、场景清理、规则调整混合；
- 每一步可按 formatter 调用点回滚。

## 场景治理的独立后续方案（非当前执行项）

1. 复制 `Demo.unity` 建立审计场景副本，不修改正式场景。
2. 编写只读计数器，区分“根层历史对象”“Workspace ComponentLayer”“WireLayer”“运行时 Spawn 对象”。
3. 在默认示例、模板加载、保存加载三种路径下采集 Play Mode 对象数和 Analyzer 输入数。
4. 再决定将历史对象迁移到禁用容器、删除，或确认为编辑器测试工件。
5. 该工作必须有场景级 Git 标签/备份及完整功能回归。
